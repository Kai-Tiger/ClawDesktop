# 图片处理实现方案（OpenRouter 优先）

## 目标

在现有 Electron 聊天链路中支持发送图片（单聊优先），让 worker 可直接调用底层模型的视觉能力，保持现有文本聊天兼容。

## 范围

- 本期实现：单聊发送图片（base64 内联），OpenRouter/OpenAI 兼容格式。
- 保留扩展点：后续可增加其他 provider adapter。
- 暂不实现：群聊发图、provider 直连多格式分发。

## 设计原则

1. 内部格式与 provider 解耦，统一存 `{ mediaType, data }`。
2. Renderer/Main IPC 不走临时文件，先走 base64。
3. 历史数据向后兼容：`content` 既支持 `string`，也支持多模态数组。
4. 持久化瘦身：不把完整图片 base64 长期写入 `chat-history.json`。

## 数据结构

```ts
type ImageInput = {
  mediaType: string; // image/png | image/jpeg | image/webp
  data: string;      // base64 body, no data URL prefix
};

type ContentBlock =
  | { type: 'text'; text: string }
  | { type: 'image'; mediaType: string; data: string };

type MessageContent = string | ContentBlock[];
```

## 分层改造

### 1) Renderer

- `ChatMessage.content` 升级为 `MessageContent`。
- `useChat.send` 升级为 `send(text, images?)`。
- Composer 支持：
  - 粘贴图片（必做）
  - 拖拽图片（必做）
  - 文件选择（可后补）
- 增加待发送图片区（缩略图、删除按钮）。

### 2) Preload / API

- `chatSend(workerId, message, images?, history?)`。
- 同步更新 `gateway.ts` 的 `GatewayApi` 类型。

### 3) Main / Gateway

- `ipcMain chat:send` payload 新增 `images`。
- `service.chat` 与 `chatHttp` 接收 `images`。
- 在 `chatHttp` 做 OpenAI 兼容转换：

```ts
{
  role: 'user',
  content: [
    { type: 'text', text: message },
    ...images.map((img) => ({
      type: 'image_url',
      image_url: { url: `data:${img.mediaType};base64,${img.data}` }
    }))
  ]
}
```

## 历史持久化策略

- 内存态可保留原图，保证当前会话预览与回放。
- 磁盘持久化前做 sanitize：图片替换为占位文本，例如 `[image:image/jpeg,size=12345]`。
- 避免 `chat-history.json` 体积无限增长。

## 约束与校验

- 单张图片默认上限：2MB。
- 单次发送最多：3 张。
- MIME 白名单：`image/png`、`image/jpeg`、`image/webp`。
- 超限/格式错误在 UI 给出即时提示并阻止发送。

## 验收标准

- 用户可在单聊中粘贴/拖拽图片并发送。
- 模型可正确识别图片内容并回复。
- 纯文本发送行为与现状一致。
- 旧历史数据可正常读取。
- 历史文件体积可控，无完整 base64 长期落盘。
