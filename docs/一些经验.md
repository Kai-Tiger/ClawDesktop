⏺ 根本原因在于 agent 进程对文件系统没有沙箱约束，分两层来理解：

---

第一层：IPC 层有保护，但 agent 不走 IPC

workerSaveSkill / workerReadSkill 这两个 IPC handler 里有路径校验：

skillPath 必须以 workspace-{workerId}/skills/ 开头

但这个校验只对"通过 UI 手动编辑 skill"生效。当 worker 自己作为 AI agent 修改 skill 时，它通过  
 openclaw CLI 的内置文件工具直接写磁盘，完全绕过 IPC 层。

---

第二层：所有 worker 的 workspace 在同一父目录下

~/.openclaw/  
 workspace-worker-a/skills/research/SKILL.md  
 workspace-worker-b/skills/research/SKILL.md ← 同名

agent 的 system prompt 里写了 canonical workspace 路径，但 LLM  
 在执行文件操作时如果用了相对路径、~/.openclaw/ 前缀、或者遍历了父目录，就会发现其他  
 workspace，然后按照"找到同名 skill 就修改"的逻辑错误地写入了别人的文件。

---

可以从哪里切入修复（思路，不写代码）

1. 在 openclaw CLI 层限制工作目录：启动 agent 子进程时设 cwd 为该 worker 的
   workspace，同时通过环境变量/参数告知 CLI 只允许在该目录内写文件。
2. 在 system prompt 里更强约束：明确禁止访问 workspace-  
   开头的兄弟目录，并把绝对路径列为唯一合法路径。
3. 文件写操作 hook：如果 openclaw CLI 支持 hook 或 middleware，在写文件前校验目标路径是否在当前
   worker 的 workspace 内，否则拒绝。
