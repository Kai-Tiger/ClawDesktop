⏺ 改动总结：

问题根源： fileContent 全量传给了协调者，协调者把它塞进 task message，消息变得巨长。

修复后的流程：
用户上传 CSV + @A @B
│
▼
协调者收到：用户原始文字 + "（附件：xxx.csv）" ← 只有文件名提示
协调者生成计划：{ task1 → workerA, task2 → workerB }
│
▼
Renderer 执行 task1（after: []）：
message = task.message + "\n\n文件内容：\n" + csvText ← 执行层直接注入
│
▼
Renderer 执行 task2（after: ["t1"]）：
message = task.message + "\n\n前置任务结果：\n" + task1的reply

协调者的 task message 只有简短的任务描述，文件内容和前置结果都由 Renderer 在执行时拼接。

根本问题：Electron App 没有 WebSocket 连接

Gateway 用 WebSocket（ws://127.0.0.1:18789）来投递 cron 消息，不是 HTTP。Electron App 目前只用  
 HTTP 发 chat completions，没有 WebSocket。

cron 任务执行完 → 尝试通过 WebSocket "webchat" channel 投递  
 → 没有 WebSocket 客户端连接 → deliveryStatus: unknown

这是 Electron App 缺失的功能。要修复，需要：

1. main process 建立并维护一个到 ws://127.0.0.1:18789 的 WebSocket 连接
2. 接收 gateway 推送的 announce 消息（cron 结果）
3. 通过 IPC 发给 renderer
4. renderer 在对应的 chat 窗口显示  


连接需要处理 gateway 的 challenge 握手（从 client-CJI3Hi9b.js 可以看到是 connect.challenge →  
 connect 的 handshake 流程）。
